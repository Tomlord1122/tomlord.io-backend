### Golang Backend Blueprint — Development Guide

This guide documents how to develop, run, and deploy a production-grade Golang backend using this project’s stack: Gin (HTTP), Viper (config), sqlc + pgx (PostgreSQL), Gorilla WebSocket, Goth (OAuth), Docker/Compose, and Fly.io.

## Overview

- **Language/Runtime**: Go (module targets 1.24.x; Go 1.22+ works)
- **Web framework**: Gin (`github.com/gin-gonic/gin`)
- **Config**: Viper (`github.com/spf13/viper`)
- **Database**: PostgreSQL, pgx pool (`github.com/jackc/pgx/v5/pgxpool`)
- **Queries**: sqlc (`sqlc.yaml`, sources in `sqlc/queries`)
- **Auth**: JWT (`github.com/golang-jwt/jwt/v5`), OAuth via Goth (Google)
- **Sessions**: `github.com/gorilla/sessions`
- **WebSocket**: `github.com/gorilla/websocket`
- **CORS**: `github.com/gin-contrib/cors`
- **Container/Deploy**: Docker, Compose, Fly.io
- **Make**: Common developer tasks
- **Frontend integration**: defaults to `FRONTEND_URL=http://localhost:5173` (e.g., pnpm dev)

## Project structure

- `cmd/api/main.go`: HTTP server boot + graceful shutdown
- `internal/server/`: server initialization, CORS, routes, handlers
- `internal/auth/`: OAuth provider setup (Google), user persistence
- `internal/middleware/`: JWT generation/validation, auth helpers
- `internal/database/`: pgx pool + sqlc query binding + health
- `internal/websocket/`: hub, client, upgrader, allowed origins
- `internal/db/`: generated by sqlc
- `internal/services/`: application services for blogs and messages
- `sqlc/queries/`: SQL query sources
- `migrations/`: SQL migrations (golang-migrate format)
- `Dockerfile`, `docker-compose.yml`, `fly.toml`, `Makefile`

## Prerequisites

- Go 1.22+
- Docker + Docker Compose
- PostgreSQL client tools (optional, for local inspection)
- golang-migrate CLI: see docs at `https://github.com/golang-migrate/migrate`
- sqlc: see docs at `https://docs.sqlc.dev/`

## Configuration

Viper loads from environment variables only. Key settings:

- **Core**
  - `APP_ENV`: `local` or `production` (default `local`)
  - `PORT`: server port (default `8080`)
  - `FRONTEND_URL`: e.g., `http://localhost:5173`
  - `ALLOWED_ORIGINS`: CSV; overrides default allowed origins for CORS/WebSockets
- **JWT/cookies**
  - `JWT_SECRET`: HMAC secret for JWT signing (set strong value in prod)
  - `SESSION_SECRET`: cookie session secret (set strong value in prod)
- **OAuth (Google)**
  - `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`
  - `GOOGLE_CALLBACK_URL`: default `http://localhost:8080/auth/google/callback` (update for prod)
- **Database**
  - `DATABASE_URL`: takes precedence if provided
  - Or individual params: `BLUEPRINT_DB_HOST`, `BLUEPRINT_DB_PORT`, `BLUEPRINT_DB_DATABASE`, `BLUEPRINT_DB_USERNAME`, `BLUEPRINT_DB_PASSWORD`, `BLUEPRINT_DB_SCHEMA` (default `public`)

Example `.env` for local dev:

```bash
APP_ENV=local
PORT=8080

# DB (local Compose)
BLUEPRINT_DB_HOST=localhost
BLUEPRINT_DB_PORT=5432
BLUEPRINT_DB_DATABASE=tomlord
BLUEPRINT_DB_USERNAME=postgres
BLUEPRINT_DB_PASSWORD=postgres
BLUEPRINT_DB_SCHEMA=public
# Or use DATABASE_URL instead:
# DATABASE_URL=postgres://postgres:postgres@localhost:5432/tomlord?sslmode=disable&search_path=public

# Auth
JWT_SECRET=dev-change-me
SESSION_SECRET=dev-change-me
GOOGLE_CLIENT_ID=your-google-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret
GOOGLE_CALLBACK_URL=http://localhost:8080/auth/google/callback

# Frontend/CORS/WS
FRONTEND_URL=http://localhost:5173
ALLOWED_ORIGINS=http://localhost:5173
```

## Running locally

### Docker Compose (recommended)

```bash
docker compose up --build
```

- App listens on `:8080` (mapped to host), DB on `:5432`
- Health: `GET http://localhost:8080/health`

### Direct Go run (DB must be reachable)

```bash
go run cmd/api/main.go
```

### Make targets

- `make build` / `make run`
- `make docker-run` (starts services, streams logs)
- `make docker-up` / `make docker-down`
- `make test`
- `make sqlc` (generate sqlc code)
- `make migrateup` / `make migratedown` (apply/revert migrations)

## Database: migrations + sqlc

Migrations reside in `migrations/` and are compatible with golang-migrate.

- Apply all migrations:

```bash
make migrateup
```

- Revert the most recent migration:

```bash
make migratedown1
```

- Create a new migration pair:

```bash
migrate create -ext sql -dir migrations -seq add_feature_x
```

sqlc generates strongly typed query code into `internal/db` from sources in `sqlc/queries`. After editing SQL, regenerate:

```bash
make sqlc
```

## HTTP API

Core routes (see `internal/server/routes.go`):

- `GET /` — hello
- `GET /health` — DB health + pool stats
- `GET /debug/jwt` — display Authorization header and parsed claims if valid
- `GET /ws` — WebSocket endpoint (optional auth)

Auth:

- `GET /auth/:provider` — start OAuth (e.g., `/auth/google`)
- `GET /auth/:provider/callback` — OAuth callback; creates/updates user, sets `auth_token` cookie, redirects to `${FRONTEND_URL}/auth/callback?token=...`
- `POST /auth/logout` — clear cookie
- `GET /auth/me` — return current user (requires auth)

Blogs:

- `GET /api/blogs?limit=&offset=&tag=&lang=&published=true`
- `GET /api/blogs/:slug`
- Non-prod only: `POST /api/blogs`, `PUT /api/blogs/:slug`, `DELETE /api/blogs/:slug`

Messages:

- `GET /api/messages/post/:slug`
- `GET /api/messages/blog/:slug`
- `POST /api/messages` (auth) — create comment
- `PUT /api/messages/:id` (auth) — edit own comment
- `DELETE /api/messages/:id` (superuser or owner)
- `POST /api/messages/:id/thumb` (auth) — toggle like

## Authentication

- OAuth via Goth (Google).
  - Start: open `http://localhost:8080/auth/google`
  - Callback must match `GOOGLE_CALLBACK_URL`
- JWT
  - Signed with `JWT_SECRET` (HS256), 24h expiry
  - Accepted via `Authorization: Bearer <token>` or cookie `auth_token`

Example calls:

```bash
# Authorized request with Bearer token
curl -H "Authorization: Bearer $TOKEN" http://localhost:8080/auth/me
```

## WebSockets

- Endpoint: `GET /ws`
- Origin checks align with HTTP CORS. Override via `ALLOWED_ORIGINS` or `FRONTEND_URL`.
- Rooms: subscribe to post/blog slugs; server broadcasts comment/like events per room.

Message types: `new_comment`, `thumb_update`, `comment_update`, `comment_delete`, `ping`, `pong`.

Browser example:

```javascript
// rooms is an array of slugs, JSON-encoded and URI-encoded
const rooms = encodeURIComponent(JSON.stringify(["my-post-slug"]));
const ws = new WebSocket(`ws://localhost:8080/ws?rooms=${rooms}`);

ws.onopen = () => {
  ws.send(JSON.stringify({ action: "subscribe", rooms: ["another-post"] }));
};

ws.onmessage = (e) => {
  const msg = JSON.parse(e.data);
  console.log("WS message", msg.type, msg.payload, "room:", msg.room);
};
```

## CORS

- Centralized in `internal/server/cors.go` using `websocket.AllowedOrigins()` to keep parity with WS.
- Methods/headers/credentials configured for SPA needs.

## Deployment

### Docker

- Build and run locally with Compose: `docker compose up --build`
- Image is built via `Dockerfile`.

### Fly.io

Config in `fly.toml`.

Typical flow:

```bash
fly auth login
fly secrets set \
  APP_ENV=production \
  JWT_SECRET=... \
  SESSION_SECRET=... \
  FRONTEND_URL=https://your-frontend.example \
  ALLOWED_ORIGINS=https://your-frontend.example \
  GOOGLE_CLIENT_ID=... \
  GOOGLE_CLIENT_SECRET=... \
  GOOGLE_CALLBACK_URL=https://your-api.example/auth/google/callback \
  BLUEPRINT_DB_HOST=... BLUEPRINT_DB_PORT=5432 \
  BLUEPRINT_DB_DATABASE=... BLUEPRINT_DB_USERNAME=... BLUEPRINT_DB_PASSWORD=... BLUEPRINT_DB_SCHEMA=public

fly deploy
```

Ensure migrations are applied (run once from a console job or CI) before serving traffic.

## Testing

```bash
make test
```

- Add unit tests under corresponding packages.
- For handlers, use Gin test context; for services, run against a test DB.

## Observability & health

- `GET /health` returns DB status and pool metrics; integrate with uptime checks.
- Add structured logging around auth flows, DB errors, and WS events as needed.

## Security checklist

- Use strong `JWT_SECRET` and `SESSION_SECRET` in production.
- Use HTTPS in production; set cookies secure (`Secure=true`).
- Restrict `ALLOWED_ORIGINS` explicitly in production.
- Store OAuth credentials and DB credentials as secrets.
- Keep non-prod-only routes disabled in production (already enforced for blog mutations).
- Validate/limit inputs in handlers/services.

## Troubleshooting

- Missing OAuth envs: boot will fail fast; set `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`/`GOOGLE_CALLBACK_URL`.
- JWT validation issues: use `GET /debug/jwt` to inspect claims/errors.
- CORS/WS origin mismatch: set `ALLOWED_ORIGINS` or `FRONTEND_URL` correctly.
- sqlc not reflecting changes: run `make sqlc` after editing SQL.
- Queries failing: ensure `make migrateup` ran and DB is reachable.

## Extending the app

1. Add a new SQL query in `sqlc/queries/*.sql`.
2. Run `make sqlc` to generate new methods in `internal/db`.
3. Wrap logic in a service (e.g., `internal/services/your_feature.go`).
4. Expose via routes/handlers in `internal/server/routes.go`.
5. Add tests and update documentation.
